# HR Database & Analytics | PostgreSQL

**SQL-проект для портфолио — Ксения Самохина**  
[English version](README.md)

## О проекте

Проект посвящён разработке реляционной базы данных для управления персоналом и анализу HR-показателей с помощью PostgreSQL. На примере вымышленной компании рассматриваются сведения о сотрудниках, отделах, должностях, заработной плате, премиях, навыках и командировках.

В работе объединены **проектирование базы данных** и **аналитика на SQL**: создание связанных таблиц, заполнение и изменение данных, анализ кадровой структуры и оплаты труда с использованием объединений, агрегатных функций, подзапросов, CTE, представлений и оконных функций.

## Цели проекта

- Создать структурированную базу данных для хранения HR-информации.
- Настроить связи между сотрудниками, должностями и отделами.
- Проанализировать распределение сотрудников и различия в заработной плате.
- Определить зарплатные рейтинги и сотрудников с оплатой выше средней по отделу.
- Продемонстрировать практическое применение SQL для обработки и анализа данных.

## Технологии

**PostgreSQL 18** · **pgAdmin 4** · **SQL** · **PL/pgSQL**

## Структура базы данных

В схеме `staff2` представлены **9 связанных таблиц**:

| Таблица | Назначение |
| --- | --- |
| `employee` | Сотрудники и занимаемые должности |
| `department` | Отделы и их расположение |
| `position` | Должности, оклады и принадлежность отделам |
| `skill` | Справочник профессиональных навыков |
| `position_skills` | Навыки, связанные с должностями |
| `accrual` | Начисления сотрудникам |
| `bonus_type` | Категории премий |
| `emp_bonus` | Назначенные сотрудникам премии |
| `b_trips` | Командировки |

**Основная цепочка связей:** `employee` → `position` → `department`. Отдельные таблицы описывают навыки, премии, начисления и командировки.

В проверенной базе, созданной с нуля, содержатся **11 сотрудников, 6 отделов, 9 должностей и 20 записей о начислениях**. Все данные вымышленные.

### 2. Сотрудники с окладом выше среднего по отделу

С помощью **CTE** и оконной функции `AVG() OVER (PARTITION BY ...)` выявлены **4 сотрудника**, чей базовый оклад превышает средний по соответствующему отделу: один в HR, один в маркетинге и двое в программировании.

### 3. Распределение сотрудников и зарплатные рейтинги

Запросы позволяют подсчитывать численность сотрудников по отделам и ранжировать их по окладу. У одного сотрудника отсутствует привязка к отделу через должность — этот случай показывает, почему при анализе важно учитывать пропущенные связи.

Результаты проверены в pgAdmin на тестовой базе, созданной с помощью SQL-скрипта.

## Как запустить проект

### Вариант 1 — Создать базу с нуля

1. Установить PostgreSQL и pgAdmin.
2. Создать в pgAdmin **новую пустую базу данных**.
3. Открыть **Query Tool** и загрузить `HR_Database_Analytics.sql`.
4. **Один раз** выполнить весь скрипт: он создаст схему `staff2`, заполнит таблицы и выполнит SQL-запросы.
5. Изучить таблицы в разделе **Schemas → staff2 → Tables**.

### Вариант 2 — Восстановить готовую базу

1. Создать **другую пустую базу данных**.
2. Нажать на неё правой кнопкой → **Restore** → выбрать `HRM_Samokhina_Ksenia.backup` (формат Custom).
3. Открыть схему `staff2`.
4. Загрузить `Analytics_After_Restore.sql` и выполнить аналитические SELECT-запросы.

**Важно:** не запускать полный скрипт повторно или поверх базы, восстановленной из резервной копии. Это два альтернативных способа запуска. Бэкап отражает другое сохранённое состояние данных, поэтому количество записей может отличаться.
